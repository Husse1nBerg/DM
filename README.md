# Marina Management System Backend

A multi-tenant marina management backend built with Go, providing APIs for marina operations, user management, and organization management.

## Project Overview

This backend powers a marina management system with the following key features:
- **Multi-tenant architecture**: Organizations, Marinas, and Users
- **Role-based access control (RBAC)**
- **Marina-specific resource management**

## Tech Stack

- **Go** (version 1.23.5)
- **Web Framework**: [Echo v4](https://github.com/labstack/echo)
- **Database**: PostgreSQL
- **Database Migrations**: [Goose](https://github.com/pressly/goose)
- **Database Access**: [SQLC](https://github.com/sqlc-dev/sqlc) with [PGX v5](https://github.com/jackc/pgx)
- **API Documentation**: [Swaggo](https://github.com/swaggo/swag) for Swagger/OpenAPI generation
- **Logging**: [Zap](https://github.com/uber-go/zap)
- **Validation**: [go-playground/validator v10](https://github.com/go-playground/validator)

## Setup and Installation

### Prerequisites

- Go 1.23.5 or later
- Docker and Docker Compose
- PostgreSQL
- Make (optional, for Makefile commands)

### Local Development Setup

1. **Clone the repository**
   ```bash
   git clone <repository-url>
   cd dm-web-backend
   ```

2. **Set up environment variables**
   ```bash
   cp .env.example .env
   # Edit .env with your configuration
   ```

3. **Start the PostgreSQL database with Docker**
   ```bash
   docker-compose up -d
   ```

4. **Run migrations**
   ```bash
   source .env
   goose -dir db/migrations postgres "postgres://${DB_USER}:${DB_PASSWORD}@${DB_HOST}:${DB_PORT}/${DB_NAME}?sslmode=disable" up
   ```

5. **Generate database code with SQLC**
   ```bash
   sqlc generate
   ```

6. **Run the application**
   ```bash
   go run cmd/api/main.go
   ```

## Local Development with Docker

To run the application locally using Docker with a PostgreSQL database:

```bash
# Copy the example environment file
cp .env.example .env

# Edit the .env file with your preferred configuration (optional)

# Start the application and database
docker-compose -f docker-compose.local.yml up -d

# Stop the containers
docker-compose -f docker-compose.local.yml down

# Stop the containers and remove volumes
docker-compose -f docker-compose.local.yml down -v
```

This setup includes:
- The application running on port 8080 (configurable in .env)
- PostgreSQL database exposed on port 5432 (configurable in .env)
- Default environment variables in .env.example:
  - Admin credentials: admin@example.com / admin123
  - Database: marina_dev
  - Database user: postgres
  - Database password: postgres

The docker-compose.local.yml file uses environment variables from the .env file with fallback values if any variables are not defined.

## Development Commands

### Generate API Documentation
```bash
swag init -g ./cmd/api/main.go -o ./docs
```
or with more specific parameters:
```bash
swag init -d ./cmd/api/,./internal/server/handlers -o ./docs -g main.go --parseInternal
```

### Create a New Database Migration
```bash
cd db/migrations && goose create <migration_name> sql
```

### Generate Database Access Code
```bash
sqlc generate
```

### Run Goose Migrations

#### Prerequisites

- **Goose**: Migration tool for PostgreSQL
  ```bash
  go install github.com/pressly/goose/v3@latest
  ```

- **Docker** (for local setup)
  ```bash
  docker-compose up -d
  ```

- **SQLC**: Tool to generate Go code from SQL queries
  ```bash
  go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
  ```

#### Apply Migrations

- **Ensure .env variables are loaded**:
  ```bash
  source .env
  ```

- **Run migrations locally**:
  ```bash
  goose -dir db/migrations postgres "postgres://${DB_USER}:${DB_PASSWORD}@${DB_HOST}:${DB_PORT}/${DB_NAME}?sslmode=disable" up
  ```

- **Run migrations in production**:
  ```bash
  goose -dir db/migrations postgres "postgres://${DB_USER}:${DB_PASSWORD}@${DB_HOST}:${DB_PORT}/${DB_NAME}?sslmode=require" up
  ```

### Hot Reloading with Air

[Air](https://github.com/cosmtrek/air) provides live reloading for Go applications during development.

#### Installation

```bash
go install github.com/cosmtrek/air@latest
```

#### Usage

1. **Start the application with Air**:
   ```bash
   air
   ```

   This will use the configuration in `.air.toml` to watch for file changes and automatically rebuild and restart the application.

2. **Customizing Air configuration**:
   
   The `.air.toml` file contains the configuration for Air. You can modify this file to change which files are watched, build commands, and more.

   Example configuration:
   ```toml
   # .air.toml
   root = "."
   tmp_dir = "tmp"
   
   [build]
   cmd = "go build -o ./tmp/main ./cmd/api"
   bin = "./tmp/main"
   include_ext = ["go", "tpl", "tmpl", "html"]
   exclude_dir = ["assets", "tmp", "vendor", "docs"]
   delay = 1000 # ms
   ```
